Zana

Build the body. You own the machine.

Zana — Swahili for tools — is an open-hardware line for the physical world: the mowers, sensor nodes, bots and cameras a home or business actually runs on. What ships is the design: FreeCAD sources, KiCad projects, printable meshes, MIT-licensed. No serial number, no cloud activation, no vendor. Today exactly one device is real — an autonomous mower — and it is prototype CAD and PCB work, not a buy-the-parts kit.

What's actually in the repo

A hardware repo is mostly binaries no build server can check, so it is worth being blunt about which parts are finished work and which are recovered prototyping.

Chassis & drivetrain

Four mowbot*.FCStd iterations — mowbot4 is current — plus wheels, moulds, motor supports, shafts, couplers (one machined from aluminium), a GT2 pulley and a castor fitting.

design files

Seven KiCad boards

TRANSMITTER in thru-hole and SMD, MAINBOARD, EMF_SENSOR, RAIN, and KiKit panel scripts for the boards meant to be etched at home.

design files

Wireless-power study

Executable Python: elliptic-integral mutual inductance, skin and proximity losses, and the k·Q efficiency solve for the charging link. The coils it recommends are re-derived by the test suite on every push.

runs · tested

Fabrication rigs

A coil winder, a PCB mill and a UV exposure box — designed so the mower's own electronics could be made in the same workshop that made the mower.

design files

Driving simulator

C++ on raylib + Bullet, native and WASM, with an earlier PyBullet prototype. It is source only: nothing builds it, nothing tests it, and it loads a mesh that is not checked in.

sketch — not built

No firmware

Worth saying plainly: there is no firmware in this repo, no bill of materials and no assembly guide. Sourcing parts and writing the control code are still yours to do.

Get the designs

There is nothing to install and no daemon to run — the deliverable is a directory of CAD. These commands are what a clean clone can actually do today.

git clone https://github.com/vul-os/zana.git
cd zana

# run the checks that gate this repo
pip install -r requirements-dev.txt
python3 -m pytest -q

# re-derive the charging-coil design
cd mower/coil-study && python3 main.py

The interesting part: charging without a plug

A mower that has to find a contact pair to charge is a mower that eventually fails on wet grass and oxide. Zana's dock is inductive, and the coil geometry was not guessed — mower/coil-study/ models it from first principles, and the write-up is checked against the model in CI.

Modelled, not tuned

Maxwell's mutual inductance between coaxial loops via complete elliptic integrals, self-inductance summed segment by segment, AC resistance with skin and proximity effects — then link efficiency from k·Q.

A design that survives a gap

Two stacked layers of 8 turns on a 200 mm inner diameter reach 91.5 % link efficiency across a 40 mm air gap at 40 kHz, in a coil 223.8 mm across and 1.5 mm thick.

Checkable, so it stays true

Every figure in DESIGN_SUMMARY.md is parsed back out of the markdown and recomputed by tests/test_coil_physics.py. The write-up and the model cannot drift apart quietly.

Zana is the body. Aql is the brain.

Two open halves of one system, each usable on its own. Splitting them keeps both honest: Zana stays a hardware project instead of growing a bespoke app per device, and Aql stays a general command centre instead of learning every board's internals.

Zana — the body

Open-hardware reference designs. Vendor-neutral: a Zana device works with any compatible control plane you already run.

Aql — the brain

The self-hosted command centre that discovers and drives your fleet from one console, local-first. github.com/vul-os/aql →

Neither requires the other

Adopt Aql without ever building a Zana device, or build a Zana device and point it at something else entirely.
